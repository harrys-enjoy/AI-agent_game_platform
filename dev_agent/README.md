# 개발 보조 에이전트 (kosa)

> 이 문서는 코드를 직접 보지 않는 분들을 위한 요약입니다. 개발자용 상세 문서는 맨 아래 링크를 참고하세요.

## 한 줄 소개

GitHub 레포에 대해 "이 PR 리뷰해줘", "브랜치 현황 정리해줘"처럼 자연어로 요청하면,
필요한 작업만 골라서 대신 처리해주는 보조 도구입니다.

## 지금 할 수 있는 것

| 요청 예시 | 하는 일 |
|---|---|
| "이 PR 리뷰해줘" | PR의 변경 내용을 읽고 파일·줄 단위로 리뷰 코멘트 작성 |
| "API 바뀐 거 있어? 문서 갱신해줘" | 엔드포인트(URL/기능) 변경을 찾아서 문서 갱신이 필요한지 알려줌 |
| "브랜치 현황 정리해줘" | 현재 브랜치·PR 목록을 보고 진행 상황 요약 문서 작성 |
| "테스트 왜 실패했어?" | 실패한 CI(자동 테스트) 로그를 읽고 원인 요약 |
| "테스트 다시 돌려줘" | GitHub Actions에서 테스트를 실제로 재실행하고 결과까지 기다림 |
| "배포해줘" / "띄워줘" | 해당 브랜치를 실제로 빌드해서 로컬에 띄움 |

한 번의 요청에 여러 개를 한꺼번에 시킬 수도 있습니다. 예: "이 PR 리뷰하고 브랜치 현황도 정리해줘."

요청에 없는 작업(특히 "테스트 재실행"과 "배포"처럼 실제로 뭔가를 실행시키는 작업)은
먼저 나서서 하지 않습니다 — 명시적으로 요청했을 때만 실행됩니다.

## 어떻게 쓰나

담당 개발자가 띄워준 웹 화면(Streamlit)에서 레포 이름과 요청 문구를 입력하면 됩니다.
별도 팀 시스템(A2A 오케스트레이터)에서 자동으로 호출되는 경로도 있습니다.

## 진행 상황

| 항목 | 상태 |
|---|---|
| PR 리뷰 / 브랜치 현황 / CI 요약 | ✅ 동작함 |
| 테스트 재실행, 로컬 배포 | ✅ 동작함 (실측 검증 완료) |
| 팀 공통 규약(A2A) 연동 | 🟡 서버는 구현됨, 팀 오케스트레이터와의 실제 연결은 아직 (Mock 상태) |
| 레포 전체 API 목록 조회 | ⬜ 아직 없음 (지금은 "이번 PR에서 뭐가 바뀌었는지"만 감지) |
| 대화 이력 기억 | 🟡 웹 화면에서는 동작, 자동 연동 경로에서는 아직 |

*(✅ 동작함 / 🟡 부분적으로 동작 / ⬜ 미착수)*

## 알아두면 좋은 점

- **리뷰 내용은 초안입니다.** AI가 작성한 리뷰나 문서 갱신 제안은 참고용이며, 실제 머지·배포 승인의 유일한 근거로 쓰지 않는 것을 권장합니다.
- 서버가 재시작되면 진행 중이던 작업은 사라집니다(임시 저장이라 그렇습니다) — 다시 요청하면 됩니다.
- 배포 결과가 "완료"로 뜨더라도 앱이 실제로 요청을 받을 준비까지는 조금 더 걸릴 수 있습니다.
