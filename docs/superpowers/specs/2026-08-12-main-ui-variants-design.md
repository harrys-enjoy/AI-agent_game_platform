# Main UI 두 가지 구성안 설계

## 목표

Main 화면의 좌측 메뉴를 단순화하고, 업무·회의 관련 기능을 Workmate AI 채팅으로 연결한다. 기존 화면은 보존하며, 새 UI를 추가해 임시 전환창으로 두 구성을 즉시 비교할 수 있게 한다.

## 메뉴 변경

- 유지: `Home`
- 변경: `Roles` → `Policies`
- 삭제: `Skills`, `Meetings`, `My Tasks`, `More`
- `Policies` 화면 제목: `Company Policies`

## UI 구성

### 기존 UI

현재의 3열 레이아웃을 유지한다.

- 좌측: Main 메뉴와 AI Chats
- 중앙: 프로젝트 작업 테이블
- 우측: Workmate AI 채팅
- 중앙의 오늘브리핑·주간업무보고 영역은 표시하지 않는다.
- 해당 위치에 Workmate AI 기능 카드 4개를 표시한다.

### 변경 UI

업무 허브형 레이아웃으로 구성한다.

- 상단: 오늘의 업무 요약과 현재 연결 상태
- 중앙: `할 일 관리`, `회의 녹음`, `회의 관리`, `회의록 검색` 빠른 실행 카드
- 중앙 하단: 프로젝트 작업 목록과 최근 활동
- 우측: Workmate AI 고정 채팅 패널
- `Policies` 선택 시 사규 카테고리·검색 중심의 전용 콘텐츠를 표시한다.

## Workmate AI 연결

빠른 실행 카드는 Workmate AI를 활성화하고 요청 문장을 입력창에 자동 삽입한다.

| 기능 | 채팅 입력 문장 |
| --- | --- |
| 할 일 관리 | 오늘 할 일과 우선순위를 정리해줘 |
| 회의 녹음 | 회의 녹음을 시작하고 회의 내용을 정리해줘 |
| 회의 관리 | 이번 주 회의 일정을 관리해줘 |
| 회의록 검색 | 회의록에서 필요한 내용을 검색해줘 |

기존 채팅 API와 세션 저장 로직은 재사용한다. 실제 외부 녹음·일정·문서 검색 연동이 없는 경우에도 카드 클릭과 채팅 요청 흐름은 정상 동작하도록 한다.

## 페이지 전환

상단에 임시 `기존 UI / 변경 UI` 전환창을 추가한다. 선택값은 `localStorage`에 저장해 새로고침 후에도 유지한다. 전환은 클라이언트 상태만 변경하며 기존 라우팅이나 백엔드 API는 변경하지 않는다.

## 접근성 및 반응형

- 모든 메뉴·카드·전환 컨트롤은 버튼과 접근 가능한 이름을 사용한다.
- 모바일에서는 3열 구조를 세로 흐름으로 전환한다.
- 카드 클릭과 키보드 포커스 상태를 구분해 표시한다.

## 검증 기준

- `Home`과 `Policies`만 Main 메뉴에 표시된다.
- 네 가지 삭제 메뉴가 Main 메뉴에서 보이지 않는다.
- 기존 UI와 변경 UI를 전환할 수 있다.
- 네 기능 카드가 Workmate AI 입력창과 연결된다.
- 기존 채팅, 작업 추가·수정, Preview 기능이 컴파일 및 동작을 유지한다.
- frontend build가 성공한다.
