# 게임 지식 데이터 작성 가이드

게임 카탈로그·도감·세계관의 직접 응답 데이터는 `data/knowledge.json`에서 관리한다. 이 데이터는 모델을 호출하지 않으므로, 검증된 짧은 사실을 빠르고 일관되게 제공하는 용도다.

## 데이터 영역

| 배열 | 용도 |
| --- | --- |
| `catalog` | 지역, 아이템, 콘텐츠 등 게임 카탈로그 |
| `codex` | 캐릭터, 몬스터, 용어, 아이템 도감 |
| `lore` | 역사, 세력, 사건, 세계관 설정 |

## 항목 형식

```json
{
  "id": "ember-village",
  "name": "잿불 마을",
  "keywords": ["잿불 마을", "잿불", "마을"],
  "answer": "잿불 마을은 화산 지대 동쪽에 있는 거점입니다."
}
```

- `id`: 배열 안에서 고유한 영문·숫자·하이픈 식별자
- `name`: 관리 화면이나 문서에서 사용할 표시 이름
- `keywords`: 사용자가 실제로 입력할 이름, 약칭, 동의어
- `answer`: 확인된 사실만 포함한 사용자용 답변

## 매칭 규칙

질문에 `keywords` 중 하나가 포함되면 해당 항목을 반환한다. 여러 항목이 맞으면 배열에서 먼저 나온 항목이 선택된다.

따라서 너무 넓은 키워드(예: `마을`, `검`, `왕`)는 가급적 피하고, 반드시 써야 한다면 더 구체적인 항목을 배열 앞쪽에 둔다. 약칭이 다른 항목과 겹치면 약칭을 제거하거나 구분 키워드를 추가한다.

## 작성 원칙

- 확인되지 않은 설정이나 추측을 `answer`에 넣지 않는다.
- 장문 설명보다 한 항목당 하나의 사실을 우선한다.
- 변경 이력, 날짜, 임시 이벤트처럼 수시로 바뀌는 정보는 데이터 갱신 절차를 정한 뒤 넣는다.
- 기획·아트 조언이 필요한 질문은 `dev-guide`를 사용한다. 이 파일은 사실 조회용이다.

## 확인 방법

데이터를 수정한 뒤 아래 명령으로 기존 직접 조회 규칙이 깨지지 않았는지 확인한다.

